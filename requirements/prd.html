YouTube Playlist Courseify — Product Requirements Document

Version: 0.1 (Initial / MVP) · Status: Draft

1. Overview

YouTube Playlist Courseify turns any public YouTube playlist into a structured, Udemy-style course. Videos are still streamed through YouTube's embedded player, while the app adds what YouTube's playlist UI lacks: progress tracking, per-video notes, completion state, and a dashboard for managing multiple courses.

Tagline: Paste a playlist link. Turn it into a course.

Goals

  • Go from a playlist URL to a watchable course in under 10 seconds.
  • Make progress (videos, watch time, %) visible at all times.
  • Let learners keep notes per video and resume exactly where they left off.
  • Work with zero sign-up: all data lives in the browser (LocalStorage).

Non-Goals (v1)

  • Authentication, accounts, or cloud sync
  • Backend or database
  • Hosting/downloading videos
  • Quizzes, certificates, social or sharing features
  • Support for private/unlisted-only playlists that the API cannot read

Target Users

Self-directed learners who follow long, sequential YouTube playlists (programming, languages, university lectures, etc.) and want a focused course experience.

2. User Stories

# As a learner, I want to… So that…
U1 paste a playlist URL and have it added as a course I don't set anything up manually
U2 watch videos in a player with the playlist beside it I can move through the course easily
U3 mark videos complete/incomplete I know what I've finished
U4 see completed count, watch time, and % I stay motivated
U5 write notes on each video I retain what I learn
U6 resume from my last watched video I don't lose my place
U7 see all my courses on a dashboard I can manage several at once
U8 remove a course I can clean up

3. Information Architecture

Based on the sketch, there are three primary views:

View Route Purpose
Input View / (or /add) Add a playlist
Dashboard /dashboard List and manage courses
Player View /course/:courseId?v=:videoId Watch, track, take notes

Routing logic: First visit with no courses → Input View. Returning user with ≥1 course → Dashboard. The Dashboard always has an "Add course" action leading to the Input View.

4. Functional Requirements

4.1 Input View

Sketch reference: A bordered page with a centered label "Enter your playlist link", a wide single-line input with an arrow/submit button at its right end, and the text "Turn it into course" below.

ID Requirement
IN-1 Centered layout with heading "Enter your playlist link", one URL input, and a submit (arrow) button inside/at the end of the input.
IN-2 Helper/CTA text: "Turn it into a course".
IN-3 Submit on button click or Enter key.
IN-4 Validate the URL client-side. Accepted formats: youtube.com/playlist?list=ID, youtube.com/watch?v=…&list=ID, youtu.be/…?list=ID. Extract list ID.
IN-5 Show inline errors: invalid URL, no playlist ID found, playlist not found/private, API/network failure, quota exceeded.
IN-6 Show a loading state (button spinner + "Fetching playlist… 50/431 videos") during fetch.
IN-7 If the playlist was already added, don't duplicate it; open the existing course and show a notice.
IN-8 On success, save the course and navigate to the Player View at the first video.

Course completion

ID Requirement
CC-1 When the last incomplete video is marked complete, show a congratulations modal/banner (confetti optional) with course title, total videos, total duration, and actions: Back to Dashboard, Rewatch.
CC-2 Completed courses show a "Completed" badge on the dashboard.
CC-3 Un-completing any video removes the completed state.

4.3 Course Progress

ID Requirement
PR-1 Track: total videos, completed videos, total duration, completed duration, completion %.
PR-2 Completed duration = sum of durations of videos marked complete + the watched portion of the in-progress video (optional refinement).
PR-3 Completion % = completed videos ÷ total videos, rounded to the nearest integer. (Open question #2: duration-weighted alternative.)
PR-4 Display format example: 12 / 30 videos completed · 4h 25m / 10h 40m watched · 41% completed.
PR-5 Progress is recalculated instantly on any completion change and is consistent between dashboard and player.

4.5 Dashboard "Fill the Space" Proposals

The sketch leaves the lower dashboard area open. Recommended for v1 (pick 2–3):

  1. Continue where you left off — a wide banner for the most recently watched video with a Resume button. (Highest value, low effort.)
  2. Learning stats — total hours watched, videos completed, courses completed, current day streak.
  3. Recent notes — last 3–5 notes with video/course links.
  4. Weekly activity — a small 7-day bar chart of videos completed or minutes watched.
  5. Quick add — an inline playlist URL field so users needn't leave the dashboard.

5. Data & Storage

All user data is stored in LocalStorage under a versioned namespace (e.g. courseify:v1:*).

5.1 Keys

Key Contents
courseify:v1:profile { name }
courseify:v1:settings { autoplayNext, autoCompleteOnEnd, autoCompleteThreshold }
courseify:v1:courses Array of course records (metadata only)
courseify:v1:course:{id}:videos Video metadata for that course
courseify:v1:course:{id}:progress Completion, positions, last watched
courseify:v1:course:{id}:notes Notes keyed by videoId

Splitting keys per course avoids rewriting one huge blob on every save.

5.2 Data Model

}

// Notes (course:{id}:notes)
{ "abc123": { "text": "…", "updatedAt": "…" } }

5.3 Storage Considerations

ID Requirement
ST-1 Wrap all reads/writes in try/catch; recover gracefully from corrupted or missing data.
ST-2 Detect QuotaExceededError (LocalStorage is ~5 MB) and show a clear message suggesting removing a course.
ST-3 Cap stored description length (e.g. 2,000 chars) to keep large playlists (400+ videos) within quota.
ST-4 Include a schemaVersion and a migration path for future changes.
ST-5 Export / Import JSON backup (recommended for v1.1) since clearing browser data erases everything.
ST-6 Sync across tabs using the storage event so two open tabs don't overwrite each other.

6. YouTube API Integration

Step Endpoint Notes
1 playlists.list (part=snippet,contentDetails) Playlist title, channel, thumbnail, item count
2 playlistItems.list (part=snippet,contentDetails, maxResults=50) Paginate with nextPageToken until complete
3 videos.list (part=contentDetails,snippet), batches of 50 IDs ISO-8601 duration (PT1H2M3S) → seconds; full descriptions

Requirements and risks:

  • Deleted/private videos appear in playlists; detect them (missing from videos.list, or title "Private video"/"Deleted video") and mark unavailable. Exclude them from totals.
  • Convert ISO-8601 durations robustly (including days for very long videos and P0D for live streams).
  • API key exposure: with no backend, the key ships in client code. Mitigate by restricting the key by HTTP referrer and to YouTube Data API v3 only. A tiny serverless proxy is the recommended upgrade path.
  • Quota: default 10,000 units/day. A 431-video playlist costs roughly 1 + 9 + 9 ≈ 19 units, so quota is not a v1 concern, but handle quotaExceeded errors.
  • Provide a manual "Refresh playlist" action to sync new/removed videos while preserving progress and notes by videoId.

7. Non-Functional Requirements

Area Requirement
Performance Dashboard renders < 1s; sidebar smooth with 500 videos; fetch of 400+ videos shows incremental progress.
Responsiveness Desktop-first, fully usable on tablet and mobile.
Accessibility Keyboard navigable, visible focus states, ARIA labels on checkboxes and player controls, WCAG AA contrast.
Privacy No accounts or tracking; data never leaves the browser (except YouTube API/embed calls). Disclose this in the UI.
Compatibility Latest Chrome, Edge, Firefox, Safari.
Reliability Progress must never be lost on refresh, tab close, or crash (save on interval + visibilitychange/beforeunload).
Theming Light and dark mode (dark strongly recommended for a learning app).

8. Suggested Tech Stack

  • Frontend: React + Vite (or Next.js in static mode), TypeScript
  • Styling: Tailwind CSS
  • State: Zustand (or Context + reducer) with a LocalStorage persistence layer
  • Routing: React Router
  • Player: YouTube IFrame Player API
  • Hosting: Vercel / Netlify / GitHub Pages (static)

9. Edge Cases

  • Playlist with 0 videos, or only unavailable videos
  • Playlist > 500 videos (still supported; warn about storage)
  • Same video appearing twice in a playlist (key by position+videoId if needed)
  • Playlist updated on YouTube after being added (Refresh action)
  • User opens the same course in two tabs
  • Video embedding disabled by the owner
  • Offline or network failure while adding (no partial course is saved)
  • User manually edits the URL to a course/video that doesn't exist → friendly 404 back to Dashboard

10. Success Metrics

Since v1 has no analytics, these apply if lightweight, privacy-friendly analytics are added later:

  • % of visits where a playlist is successfully added
  • Courses added per user
  • Return rate (users opening a course on day 2+)
  • Average completion % per course
  • Notes created per course

12. Open Questions

  1. Display name: first-run prompt, or a settings field? (The sketch shows a personalized greeting but there is no auth.)
  2. Completion %: by video count (simple, matches the 58/431 · 12% sketch) or by watched duration?
  3. Auto-complete: should videos auto-complete at end / 90%, or only be manual?
  4. Notes format: plain text only, or Markdown with preview?
  5. API key strategy: ship a restricted key in the client for v1, or add a small serverless proxy from day one?
  6. Playlist refresh: manual only, or auto-check on course open?
  7. Which dashboard "fill space" widgets (see §4.5) should ship in v1?
