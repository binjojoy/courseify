# Courseify

Turn any public YouTube playlist or single video into a structured, navigable course with progress tracking, timestamped notes, and AI-generated study guides.

Courseify has no accounts and no tracking. Your courses, progress, notes, and study guides live in your browser's local storage. The only external service you ever talk to is Google's Gemini API, and only if you supply your own key.

## Features

**Learning**

- Paste a playlist or single-video URL to build an ordered lesson tree.
- YouTube's own player controls, with playback resuming at your last saved position.
- Lessons auto-complete at 90% watched or on end, and optionally auto-advance to the next one.
- Per-lesson markdown notes with an `Insert timestamp` button; clicking a timestamp in your notes seeks the video.
- Dashboard with watch time, completion progress, and recently edited notes.
- Command palette for jumping to a lesson or running an action by keyboard.
- Light and dark themes.

**AI study guides**

- Optional per-lesson study guide generated by Google Gemini.
- Five sections: Summary, Highlights, Notes, Flashcards and a 10-question Quiz.
- Bring your own Gemini API key; it is stored locally and never reaches our backend.
- Transient Gemini failures are retried automatically with backoff.

**Data**

- Export and import a full JSON backup, with merge or replace on conflict.
- No accounts, no telemetry, no server-side storage of anything you own.

## Quick start

Requires [Node.js](https://nodejs.org/) 18 or newer. On macOS or Linux:

```bash
git clone https://github.com/binjojoy/courseify.git
cd courseify
bash setup-and-run.sh
```

That single command installs both workspaces, starts the API on port 5000 and the app on port 5173, and opens your browser. Press `Ctrl+C` to stop both services; their output is written to `backend-dev.log` and `frontend-dev.log`.

The script needs `bash`, so on Windows use [Git Bash](https://gitforwindows.org/) or [WSL](https://learn.microsoft.com/windows/wsl/install). If you would rather start the two services yourself, follow [Manual setup](#manual-setup).

## Manual setup

```bash
git clone https://github.com/binjojoy/courseify.git
cd courseify
```

**Backend** (terminal one):

```bash
cd backend
npm install
npm run dev        # http://localhost:5000
```

**Frontend** (terminal two):

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
```

The frontend proxies `/api` to the backend in development, so no configuration is required to get started.

## Configuration

The backend reads these from `backend/.env`. All are optional; copy `backend/.env.example` to get started.

| Variable | Purpose |
| --- | --- |
| `PORT` | API port. Defaults to `5000`. |
| `FRONTEND_URL` | Comma-separated list of browser origins allowed to call the API. Defaults to `https://youtubecourseify.vercel.app,http://localhost:5173`. |
| `YOUTUBE_API_KEY` | Enables the official YouTube Data API v3 instead of the built-in scraper. |

`YOUTUBE_API_KEY` is a server-side secret. Never prefix it with `VITE_` — Vite inlines any `VITE_*` variable into the client bundle and would publish the key to every visitor. The backend ignores and warns about such variables.

Without a key, Courseify falls back to a scraper that reads public playlist metadata directly. That fallback is rate-limited by YouTube and is less reliable than the official API, so a key is recommended for regular use.

## AI study guides

Optional, and off until you provide a key. Open the profile menu and choose **Gemini API key settings**, then paste a key from [Google AI Studio](https://aistudio.google.com/).

Press **Generate study guide** on any lesson. The guide is built from that lesson's title and description and contains:

- a one-sentence summary
- 8 to 12 specific takeaways
- detailed markdown notes
- timestamped highlights you can click to jump to that moment
- a 10-question multiple-choice quiz, which doubles as a flashcard deck

Guides are saved per lesson and reappear on your next visit.

**What is sent to Google:** the lesson title and the first 4,000 characters of its description. Courseify has no access to video transcripts and does not claim to. The request goes from your browser directly to Google; the key and the prompt never pass through the Courseify backend.

**Cost and limits:** requests are billed to your own Google account. The settings dialog shows tokens returned to this browser so you can keep an eye on usage; Google does not expose remaining quota to the client, so check AI Studio for authoritative limits. When Gemini is briefly overloaded the app retries automatically with exponential backoff rather than failing on the first error, and says so while it waits.

## Privacy and data

**No accounts.** There is no sign-up, no login, and no user database.

**No tracking.** Courseify contains no analytics, telemetry, advertising, or third-party tracking scripts. The only outbound request from the frontend is the lesson metadata call to the API you are running, and — if you enable AI guides — your own Gemini request.

**Everything is local.** Courses, lesson lists, progress, watch time, notes, settings, favourites, and AI guides are stored in your browser's local storage under `courseify:*` keys. Nothing you own is kept on a server, which also means clearing your browser data clears Courseify — so export a backup before you do.

**You own your key.** A Gemini key is stored under `courseify:gemini-api-key` in your browser and sent only to Google. **Clear all data** in the profile menu removes it along with everything else, including saved AI guides and usage counters.

**Backup and restore.** Export produces a single JSON file containing your courses, progress, and notes. Import validates the file, reports why it was rejected if it is not a usable Courseify backup, and caps uploads at 10 MB. When a backup overlaps existing data you choose explicitly: **merge** (default — keeps what you have, adds what is new, and never downgrades a completion you earned) or **replace** (restores the backup exactly). Nothing is written until you confirm.

**Backend hardening.** All `/api` routes are checked against an exact origin allow-list and rejected with `403 ORIGIN_NOT_ALLOWED` otherwise, so a lookalike domain cannot spend this service's quota. Requests are rate limited per IP, bodies are size-capped, and upstream error messages are sanitised so the `YOUTUBE_API_KEY` can never be echoed back to a caller.

## Deployment

Deploy the frontend to Vercel and the backend to Render.

**Render (backend)**

- Root directory: `backend`
- Build command: `npm install`
- Start command: `npm start`
- Environment: `YOUTUBE_API_KEY`, and `FRONTEND_URL` set to your deployed frontend origin

`PORT` is assigned by Render. `FRONTEND_URL` is required in production: without it the API falls back to a default allow-list. Origins are matched exactly, so `*.vercel.app` wildcards are not supported and preview deployments must be listed explicitly.

**Vercel (frontend)**

- Root directory: `frontend`
- Framework preset: `Vite`
- Build command: `npm run build`
- Output directory: `dist`
- Environment: `VITE_API_URL=https://your-backend.onrender.com` (no trailing slash)

## API reference

| Method | Path | Notes |
| --- | --- | --- |
| `GET` | `/api/health` | Liveness check. |
| `GET` | `/api/sample-courses` | Static sample catalogue, no upstream call. |
| `GET` | `/api/playlist?url=…` | Playlist or single-video metadata and lesson list. |
| `POST` | `/api/playlist` | Same, with the URL in a JSON body. |
| `GET` | `/api/video/:videoId/description` | Lesson description text. |

Every `/api` route is origin-checked, rate limited per IP (30 playlist and 60 description requests per minute), and capped at 200 lessons per page. A truncated response carries `truncated: true` and `totalItemCount`, and the UI says so rather than implying the course is complete.

## Tests

```bash
cd backend && npm test        # unit tests for URL parsing, origin policy, duration parsing, truncation
cd frontend && npm run test:e2e   # Playwright, desktop and mobile viewports
```

`test:e2e` builds the app before serving it, so it always exercises current source rather than a stale bundle. A type error fails the run at the build step.
